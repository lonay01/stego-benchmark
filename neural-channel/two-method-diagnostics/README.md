# InvisMark / ChunkySeal neural-channel diagnostics

This is an isolated investigation, not a replacement benchmark. The production
embedding bank and completed neural run are **read-only inputs**. Nothing in
their records, releases, checkpoint identities or scores is repaired in place.

## Run

Upload `dist/InvisMark_ChunkySeal_NEURAL_DIAGNOSTICS.ipynb` to Colab and upload
the matching `_source.zip` when prompted. Use the **same A100 runtime type** as
the completed neural canary, with high RAM. Do not use the runtime running the
digital experiment. Select “Run all”; keep the browser open until the run ends.
The code also works in a Linux/NVIDIA notebook with the three paths adjusted.

Default paths under `MyDrive`:

- `watermarking_production_bank_v1`: existing carriers, read only.
- `watermarking_neural_channel_v1`: completed neural canary, read only.
- `watermarking_neural_two_method_check_v1`: new diagnostic evidence.

The controller and each decoder have separate environments. The source archive
includes the exact old neural release, not a moving GitHub branch. Its SHA-256
is checked. Installation/checkpoint download time is not estimated as inference
time. Completed evidence survives runtime loss: rerun the same notebook, with
the same settings. A heartbeat and persistent stage log show work in progress.
No background execution/Colab lifetime guarantee is made.

## Fixed design

- First five historical COCO IDs; **all five full messages**; Native only scored.
  InvisMark's reserved UUID positions are not counted as the 94 information
  bits; the complete 100-bit output and reserved errors are also retained.
  ChunkySeal uses all 1,024 message bits. No common-30 subset, ECC or voting.
- Clean, lossless PNG round trip, float normalization round trip, resize-only,
  JPEG quality 95 (subsampling 0), and unwatermarked source-crop controls.
  JPEG and source-crop results are diagnostic, not additional benchmark rows.
- Original VAE one/two passes; `sdxl_0.15_r1`; `ip2p_lighting_r1`.
  These are fixed before decoding, not selected for favourable BER.
- The exact historical per-image **all-mode batch order and width** are replayed
  for generation, although only Native outputs are retained/scored. Filtering
  to Native before batching would not recreate the old numerical experiment.
- VAE one-pass float RGB is retained separately. Its rounded pixels must equal
  the normal VAE output. Direct decoding before/after RGB8 serialization isolates
  quantization loss; the float result never replaces the official PNG score.
- Every saved PNG is decoded through the frozen benchmark adapter and a direct
  call to its loaded upstream model. Forward hooks record actual extractor-input
  shapes, dtypes, ranges and hashes. This tests the IO adapter, **not** an
  independently trained model or an independent reproduction of the paper.
- Clean is replayed twice without averaging and must match the full historical
  decoded bit vector. Same-byte historical attacked PNGs must also decode to the
  same bits. Different regenerated bytes are reported, not overwritten or passed
  off as an exact replay. Different execution identities stop the replay.
- Original images, metadata, historical row snapshots, model provenance, raw
  decoded bits, probability/logit margins, hashes, PSNR/SSIM, retained PNG/float
  examples, contact sheets and row-level CSVs are saved in the new directory.

## Reading the report

`REPORT.md` distinguishes incomplete work, IO disagreement, historical drift,
and completed agreement. High BER alone is **not a software failure**. Agreement
between paths plus correct Clean supports robustness loss under these attacks;
it does not prove general correctness or reproduction of paper tables. Inspect
`gallery/` as well. No automatic tuning, model exclusion, main-run edits or full
100-image launch follows this diagnostic.

All small diagnostic images are retained deliberately (normally hundreds of MB,
not millions of files). Only owned, disposable decoder installation slots are
cleaned between methods; the old bank and old neural results are never deleted.

## Upstream interfaces inspected

- [InvisMark Watermark._decode](https://github.com/microsoft/InvisMark/blob/main/train.py):
  normalized RGB, configured resize, decoder probabilities; the runtime uses the
  **pinned source/checkpoint from the bank**, not this moving documentation link.
- [VideoSeal / ChunkySeal](https://github.com/facebookresearch/videoseal):
  `detect(..., is_video=False)`, message logits after the detection coordinate.
  The retained model card and installed source identify the actual version.

## Local verification

`python build.py` builds the notebook and readable source ZIP. Every code cell
and shipped Python module is parsed/compiled. `python -m unittest discover -s
tests -v` runs CPU contract and mocked end-to-end tests. Real checkpoint/CUDA
success is intentionally not claimed before running the supplied notebook.
